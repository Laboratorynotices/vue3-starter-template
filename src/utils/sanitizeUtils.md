# sanitizeUtils

Утилитарный модуль `src/utils/sanitizeUtils.ts` для санитайзинга недоверенных строк (например, полученных из API). Приводит значение к безопасной однострочной строке: убирает управляющие и невидимые символы, схлопывает пробелы и при необходимости ограничивает длину.

Сейчас модуль состоит из одной функции `toPlainText` и используется в `seoUtils.ts` перед записью данных в `document.title` и мета-теги.

## Обзор

Всё, что приходит извне, нельзя считать надёжным, даже если сегодня API собственный: завтра данные могут прийти из CMS, от стороннего сервиса или после чьей-то ошибки при редактировании. Даже обычный текст может содержать:

- переводы строк и табуляцию, которые ломают однострочные поля (`title`, значения мета-тегов);
- невидимые символы (нулевой ширины, мягкий перенос, BOM), которые портят поиск и сравнение строк;
- bidi-переопределения и изоляторы, с помощью которых можно визуально поменять порядок символов и замаскировать подмену (атаки типа «Trojan Source»);
- слишком длинные значения.

`toPlainText` решает эти задачи одним вызовом и всегда возвращает значение типа `string`.

| Вход                        | Результат                                            |
| --------------------------- | ---------------------------------------------------- |
| Строка                      | Нормализованная, очищенная, однострочная, обрезанная |
| Любое значение другого типа | Пустая строка `""`                                   |

> **Важно.** Это **не экранирование HTML**. Результат безопасен для `textContent`, `document.title` и `meta.content`, но его нельзя вставлять в `innerHTML`. Подробнее — в разделе [Где можно и где нельзя использовать результат](#где-можно-и-где-нельзя-использовать-результат).

## Как это работает

Цепочка обработки для строки:

1. `normalize("NFC")` приводит строку к канонической форме, чтобы одинаково выглядящие строки были одинаковыми и по содержимому. Например, `e` + комбинирующий акут (`e\u0301`) превращается в один символ `é`.
2. `replace(UNSAFE_CHARS, " ")` заменяет опасные и невидимые символы **пробелом**, а не пустой строкой. Если бы символы просто вырезались, соседние слова могли бы склеиться.
3. `replace(/\s+/g, " ")` схлопывает любую последовательность пробельных символов в один пробел. Вместе с предыдущим шагом это делает результат однострочным.
4. `trim()` убирает пробелы по краям.
5. `slice(0, maxLength)` ограничивает длину. При значении по умолчанию (`Infinity`) обрезки нет.

Если на входе не строка, функция сразу возвращает `""`.

## Константы

### UNSAFE_CHARS

```typescript
const UNSAFE_CHARS =
  /[\p{Cc}\u00AD\u200B\u2060\uFEFF\u202A-\u202E\u2066-\u2069]/gu;
```

Регулярное выражение, описывающее символы, которые нужно заменить пробелом. Константа не экспортируется.

- Флаг `u` включает поддержку Unicode-свойств (`\p{Cc}`).
- Флаг `g` нужен, чтобы заменялись все вхождения, а не только первое.

> Регулярное выражение с флагом `g` хранит состояние (`lastIndex`). В `String.prototype.replace` это не создаёт проблем, потому что метод сбрасывает позицию сам. Но если когда-нибудь использовать эту константу с `RegExp.prototype.test()`, состояние начнёт «прилипать» между вызовами, и результаты станут нестабильными.

## Функции

### toPlainText

```typescript
toPlainText(value: unknown, maxLength?: number): string
```

Приводит значение к безопасной однострочной строке.

**Параметры:**

- `value` (unknown) — значение для обработки. Принимается любой тип, чтобы можно было передавать данные из API без предварительных проверок.
- `maxLength` (number, по умолчанию `Infinity`) — максимальная длина результата в единицах UTF-16 (то есть как у `String.prototype.length`).

**Возвращает:** `string`. Если `value` не строка (в том числе `null`, `undefined`, число, объект, массив и даже обёртка `new String("...")`), возвращается пустая строка. Числа в строки **не** преобразуются.

**Исключения:** не бросает.

**Пример:**

```typescript
toPlainText("  Привет,\n\tмир!  "); // "Привет, мир!"
toPlainText(null); // ""
toPlainText("Длинный заголовок страницы", 10); // "Длинный за"
```

## Какие символы обрабатываются

### Заменяются пробелом

| Символы           | Что это                                                                                                          |
| ----------------- | ---------------------------------------------------------------------------------------------------------------- |
| `\p{Cc}`          | Управляющие символы: C0 (`U+0000`–`U+001F`, в том числе `\n`, `\r`, `\t`, `NUL`), `DEL` и C1 (`U+0080`–`U+009F`) |
| `\u00AD`          | Мягкий перенос (невидим, пока слово не переносится)                                                              |
| `\u200B`          | Пробел нулевой ширины                                                                                            |
| `\u2060`          | «Соединитель слов» (Word Joiner), невидим                                                                        |
| `\uFEFF`          | BOM / неразрывный пробел нулевой ширины                                                                          |
| `\u202A`–`\u202E` | Bidi-встраивания и переопределения (LRE, RLE, PDF, LRO, RLO)                                                     |
| `\u2066`–`\u2069` | Bidi-изоляторы (LRI, RLI, FSI, PDI)                                                                              |

### Намеренно сохраняются

| Символы                       | Почему                                                             |
| ----------------------------- | ------------------------------------------------------------------ |
| `\u200D` (ZWJ)                | Участвует в составных эмодзи и в написании ряда письменностей      |
| `\u200C` (ZWNJ)               | Обязателен, например, в персидском языке                           |
| `\u200E`, `\u200F` (LRM, RLM) | Нужны для корректного отображения смешанного по направлению текста |

### Обрабатываются косвенно

Символы, которые не входят в `UNSAFE_CHARS`, но попадают под `\s` на шаге 3: обычный пробел, неразрывный пробел (`U+00A0`), другие пробельные символы Unicode, а также разделители строк и абзацев (`U+2028`, `U+2029`). Все они превращаются в одиночный обычный пробел.

## Где можно и где нельзя использовать результат

**Безопасно:**

- `document.title`;
- `meta.content` и другие атрибуты, устанавливаемые через DOM-свойства или `setAttribute`;
- `element.textContent`;
- интерполяция в шаблонах Vue (`{{ value }}`): Vue сам экранирует вывод.

**Небезопасно:**

- `innerHTML`, `insertAdjacentHTML`, `v-html`: функция не удаляет и не экранирует HTML-теги;
- атрибуты, содержащие URL (`href`, `src`, `action`): строка вида `javascript:...` пройдёт без изменений, для ссылок нужна отдельная проверка схемы;
- любые контексты, где нужна защита от внедрения (SQL, shell и прочее): это не их задача.

```typescript
toPlainText("<script>alert(1)</script>"); // "<script>alert(1)</script>" (без изменений)
```

## Примеры использования

### Заголовок и мета-теги

Так функция используется в `applySeo` из `seoUtils.ts`:

```typescript
document.title = toPlainText(seo.title, 200);
updateMetaTag("description", toPlainText(seo.description, 500));
updateMetaTag("keywords", toPlainText(seo.keywords, 500));
```

### Поведение на типичных входах

```typescript
// Переводы строк и табуляция превращаются в пробелы
toPlainText("Заголовок\nвторая строка\tи табуляция");
// "Заголовок вторая строка и табуляция"

// Невидимые символы заменяются пробелом, а не вырезаются
toPlainText("Hello\u200BWorld"); // "Hello World"

// Bidi-переопределение
toPlainText("a\u202Eb"); // "a b"

// Нормализация NFC
toPlainText("e\u0301"); // "é" (один символ U+00E9)

// ZWNJ и ZWJ сохраняются
toPlainText("a\u200Cb") === "a\u200Cb"; // true

// Не-строки
toPlainText(undefined); // ""
toPlainText(42); // ""
toPlainText({ title: "x" }); // ""
```

### Обработка нескольких полей

```typescript
const safe = {
  title: toPlainText(item.title, 200),
  description: toPlainText(item.description, 500),
};
```

## Обработка ошибок и отладка

Функция не бросает исключений и не пишет в консоль, поэтому о том, что значение было изменено, она не сообщает. Если нужно заметить такую ситуацию (например, при отладке данных от API), сравните вход и выход:

```typescript
const clean = toPlainText(raw, 200);

if (typeof raw !== "string") {
  console.warn("Ожидалась строка, получено:", typeof raw);
} else if (clean !== raw) {
  console.warn("Значение было изменено санитайзингом:", { raw, clean });
}
```

### Типичные неожиданности

| Симптом                                            | Причина                                                                           |
| -------------------------------------------------- | --------------------------------------------------------------------------------- |
| Пустая строка вместо числа                         | Не-строки не преобразуются: приведите значение к строке до вызова                 |
| Результат короче, чем `maxLength`                  | Обрезка выполняется после схлопывания пробелов, длина считается уже по результату |
| Пробел в конце результата при заданном `maxLength` | `trim()` вызывается до `slice`, и граница обрезки может попасть на пробел         |
| Пропали последние символы                          | Передан отрицательный `maxLength`: `slice(0, -n)` отрезает с конца                |
| Пустой результат при `maxLength = NaN`             | `slice(0, NaN)` трактует `NaN` как `0`                                            |
| Битый символ в конце                               | Обрезка разрезала суррогатную пару (например, эмодзи)                             |

## Ограничения и особенности

1. **Не экранирование HTML и не защита URL.** См. [Где можно и где нельзя использовать результат](#где-можно-и-где-нельзя-использовать-результат).
2. **Только строки.** Любой другой тип превращается в `""`, включая числа и обёртки `new String()`.
3. **Нет проверки `maxLength`.** Отрицательные значения и `NaN` дают неожиданный результат (см. таблицу выше). Рассчитано на передачу положительных чисел или значения по умолчанию.
4. **Обрезка по единицам UTF-16.** `slice` может разрезать суррогатную пару посередине, и на конце окажется одиночный суррогат. Для заголовка на 200 символов это редкость. Кроме того, могут быть разорваны графемные кластеры (например, составные эмодзи).
5. **Возможный пробел в конце после обрезки.** `trim()` выполняется до `slice()`.
6. **Не все невидимые символы покрыты.** За пределами `UNSAFE_CHARS` остаются, например, метка арабской буквы `U+061C`, невидимые математические операторы `U+2061`–`U+2064`, устаревшие управляющие форматирующие символы `U+206A`–`U+206F` и «теги» `U+E0000`–`U+E007F`. Для задач, где важна их фильтрация, список нужно расширить.
7. **Нет защиты от похожих символов.** Подмену латинских букв кириллическими и подобные омоглифы функция не обнаруживает. Нормализация NFC объединяет только канонически эквивалентные последовательности, но не «похожие» символы.
8. **Потеря информации.** Заменённые символы не восстанавливаются, а переводы строк в тексте (например, в описаниях) теряются. Для многострочных полей эта функция не подходит.
9. **Одиночные суррогаты во входных данных** не обрабатываются и сохраняются в результате.

## Возможные улучшения

Пока это предложения, в модуле они не реализованы.

**Повторный `trim` после обрезки**, чтобы не оставлять пробел на конце:

```typescript
.slice(0, maxLength)
.trim()
```

**Нормализация `maxLength`**, чтобы отрицательные значения и `NaN` не давали неожиданных результатов:

```typescript
const limit = Number.isFinite(maxLength)
  ? Math.max(0, Math.trunc(maxLength))
  : Infinity;
```

Обратите внимание: при такой записи `NaN` будет трактоваться как «без ограничения», а не как `0`. Нужно ли это, зависит от желаемого поведения.

**Обрезка без разрыва символов.** Простой вариант: `Array.from(str).slice(0, n).join("")` (не разрывает суррогатные пары, но может разорвать графемные кластеры). Более точный: `Intl.Segmenter` с гранулярностью `grapheme`.

**Расширение набора символов** в `UNSAFE_CHARS` (например, `\u061C`, `\u2061-\u2064`, `\u206A-\u206F`, `\u{E0000}-\u{E007F}`). Добавлять их нужно осознанно, с учётом легитимных языков и случаев использования.

**Многострочный вариант** (например, `toPlainMultilineText`), если появятся поля, где переводы строк нужны.

**Отдельная функция для URL** с проверкой допустимых схем (`http`, `https`, `mailto`), если приложение начнёт получать ссылки из API.

**Логирование изменений** в режиме разработки: предупреждение, если результат отличается от входной строки (см. раздел про отладку).

**Тесты** (Vitest). Пример набора:

```typescript
import { describe, expect, it } from "vitest";
import { toPlainText } from "@/utils/sanitizeUtils";

describe("toPlainText", () => {
  it("возвращает пустую строку для не-строк", () => {
    expect(toPlainText(null)).toBe("");
    expect(toPlainText(undefined)).toBe("");
    expect(toPlainText(42)).toBe("");
    expect(toPlainText({})).toBe("");
  });

  it("заменяет переводы строк и табуляцию пробелами", () => {
    expect(toPlainText("a\nb\tc")).toBe("a b c");
  });

  it("заменяет невидимые и bidi-символы пробелом", () => {
    expect(toPlainText("a\u200Bb")).toBe("a b");
    expect(toPlainText("a\u202Eb")).toBe("a b");
  });

  it("сохраняет ZWJ, ZWNJ, LRM и RLM", () => {
    expect(toPlainText("a\u200Cb\u200Dc\u200Ed\u200Fe")).toBe(
      "a\u200Cb\u200Dc\u200Ed\u200Fe",
    );
  });

  it("нормализует строку в NFC", () => {
    expect(toPlainText("e\u0301")).toBe("\u00E9");
  });

  it("схлопывает пробелы и обрезает края", () => {
    expect(toPlainText("  a   b  ")).toBe("a b");
  });

  it("ограничивает длину", () => {
    expect(toPlainText("abcdef", 3)).toBe("abc");
  });

  it("не меняет HTML-теги (это не экранирование)", () => {
    expect(toPlainText("<b>x</b>")).toBe("<b>x</b>");
  });
});
```

## Совместимость

- **TypeScript**: 4.0+. Для регулярного выражения с `\p{...}` и флагом `u` рекомендуется `target` не ниже ES2018.
- **Браузеры**: все современные браузеры с поддержкой Unicode property escapes в регулярных выражениях (ES2018) и `String.prototype.normalize` (ES2015).
- **Окружение тестов**: Node.js 10+ (для `\p{...}`), Vitest с jsdom или без него: DOM не нужен.
